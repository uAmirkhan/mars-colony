## Шаг 1. `check-model.mjs` по всем файлам `design/models/*.glb`

Команда:
```
for f in design/models/*.glb; do node design/tools/check-model.mjs "$f"; done
```

Файлов в папке — **36**, не 35: `shuttle.glb`, `shuttle-2000.glb`,
`shuttle-20000.glb`, `shuttle-v2-1536.glb` — четыре файла на один объект
(варианты децимации/текстуры), остальные 32 — по одному на модель. Сумма
групп оркестратора (12+14+7=33) считает `shuttle` один раз, без вариантов —
значит расхождение "35" в тексте плана против фактических 33 классифицированных
+ 3 служебных варианта шаттла — это неточность формулировки плана, а не
пропавшая модель. Полный список файлов сверен, ни одна модель из трех групп
плана не пропущена ни в одну сторону.

**Главный факт по всей партии**: `design/models/*.glb` — это СЫРАЯ геометрия
до децимации (470-500 тыс. треугольников, как и написано в плане). Поэтому
СЕЙЧАС `check-model.mjs` отклоняет («стоп») все 32 неклассифицированных как
служебные файла кроме `shuttle-2000.glb` — но ИСКЛЮЧИТЕЛЬНО по числу
треугольников (лимит 12000). Это ожидаемый, задокументированный в плане шаг
конвейера (децимация еще не проведена), а не дефект: как только полигонаж
срежут, для большинства моделей останутся уже другие пометки — foreign-текстура
(заметка) и, для части моделей, вырождение габарита (стоп).

Полный вывод по всем 36 файлам сохранен для отчета.
