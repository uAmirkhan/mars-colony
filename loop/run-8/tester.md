### НАХОДКА — новые примитивы кромки/стены выпадают из ВСЕХ трех проверок сцены

`check-scene3d.mjs` фильтрует три свои проверки (`silhouette_stacking`,
`ground_contact`, `occlusion`) по `o.kind === 'prop'`. Пять новых объектов
этого прогона — `pit_rim_east`, `pit_rim_south`, `pit_rim_west`,
`pit_wall_south`, `pit_wall_west` — все имеют `"kind": "terrain"`
(`support_y: null`, `support_kind: "нет"`). Ни один из них не проверяется НИ
ОДНОЙ из трех проверок раскладки: не на "парит", не на "тонет", не на
перекрытость, не на ложную опору. `red_total=0` в отчете артиста — правда, но
она ничего не говорит про эти пять объектов: они физически не участвовали в
подсчете. Это не значит, что они дефектны сами по себе (для террейн-плиток
это ожидаемое исключение, объяснено в самом коде проверки — грунт не проверяют
на "висит ли он над грунтом"), но означает, что заявление "красное 0, все
раскладочные проверки зеленые" в отчете scene-artist по факту не покрывает
новую геометрию находки 2. Пришлось проверять вручную (см. ниже) — и ручная
проверка нашла реальный дефект, который автоматика не могла увидеть в
принципе.

Воспроизведение:
```
node -e "
const s=require('./colony3d-scene.json');
for (const n of ['pit_rim_east','pit_rim_south','pit_rim_west','pit_wall_south','pit_wall_west'])
  console.log(n, s.objects.find(o=>o.name===n).kind);
"
```
Вывод: все пять — `terrain`.

### НАХОДКА — щель в углу карьера, ровно там, где чинили "карьер без объема"

Стены `pit_wall_south` и `pit_wall_west` не сходятся в углу — между ними
геометрическая щель 0.025 юнита по X, сквозь которую виден пол/фон. Проверено
и числом, и картинкой.

**Числом** (координаты по `SceneBuilder3D.cs:1341-1393`, `BuildPitDetail`,
`cx=-1`):
- `pit_wall_south`: центр `(cx, -0.5, cz-1.05)`, размер `(1.85, 1.05, 0.20)` →
  X-диапазон `[-1.925, -0.075]`.
- `pit_wall_west`: центр `(cx-1.05, -0.5, cz)`, размер `(0.20, 1.05, 1.85)` →
  X-диапазон `[-2.15, -1.95]`.
- Зазор между `-1.95` (правый край west) и `-1.925` (левый край south) =
  **0.025 юнита, ни одна из двух коробок его не покрывает**.

Для сравнения — рим-примитивы (`pit_rim_south`/`pit_rim_west`) в том же углу
сделаны толще (0.30 против 0.20 у стен) и НЕ имеют этой проблемы: их
X-диапазоны `[-1.925,-0.075]` и `[-2.2,-1.9]` перекрываются на 0.025 юнита —
угол закрыт. У стен та же офсетная формула, но меньшая толщина не
скомпенсирована — отсюда щель.

Команда воспроизведения (арифметика, без Unity):
```
node -e "
const cx=-1;
const southX=[cx-1.85/2, cx+1.85/2];
const westX=[cx-1.05-0.20/2, cx-1.05+0.20/2];
console.log('south x', southX, 'west x', westX, 'gap', southX[0]-westX[1]);
"
```
Вывод: `gap 0.025` (положительное число = дыра, не перекрытие).

**Картинкой** — щель видна и в веб-скриншоте, и в кадре редактора (более
резкий, без сглаживания), сквозь неё проступает цвет пола/фона вертикальной
полосой прямо в ближнем к камере углу карьера, то есть в самой заметной точке
находки 2:
- `colony3d-web.png`, кроп `740,600,110,130` (масштаб 6) —
  `pit-seam-run8.png` (сохранен в scratchpad проверки).
- `colony3d-editor.png`, кроп `930,750,140,160` (масштаб 5) —
  `pit-seam-editor-run8.png`.

Команда:
```
node crop.mjs colony3d-web.png 740 600 110 130 6 out.png
node crop.mjs colony3d-editor.png 930 750 140 160 5 out2.png
```

**Значимость**: находка 2 прогона ("карьер без объема", -10 по рубрике) чинилась
именно вставкой стен, чтобы карьер читался объемным телом, а не плоским пятном.
Результат содержит новый, отдельный визуальный дефект — сквозную щель в стене,
ровно в момент, когда камера смотрит на этот угол ближе всего. Автоматика его
не ловит (см. предыдущую находку: стены — `kind: terrain`, вне всех трех
проверок), поэтому "ПРОВЕРКИ СЦЕНЫ: зеленое" в отчете не является доказательством
отсутствия визуальных дефектов у новой геометрии. Не блокирующий бюджет/экономику,
чисто визуальный, но именно в той детали, которую и просили исправить.

## Шаг 4. `measure-cold.mjs` — метод и пересчет

Прочитан построчно. Формула HSV — стандартная (max/min по каналам, деление
на 6 секторов hue, коррекция отрицательного `h` через `+360`), эквивалентна
классическому алгоритму. Канал считается с шагом `info.channels` (4, alpha
пропускается корректно через `ensureAlpha()` + шаг цикла). Порог `S>=0.25`,
диапазон холодного `hue` 150-260, знаменатель — насыщенные пиксели, а не все
пиксели кадра — совпадает с методом инспектора, который grep подтвердил в
`art-inspector-baseline.md` run-7 (та же тройка чисел: 0.25 / 150-260 /
доля от насыщенных). Никакой подгонки/особых исключений в коде не найдено.

Пересчет самостоятельно:
```
node measure-cold.mjs colony3d-web.png
```
```json
{
  "saturated_pixels": 947206,
  "cold_pixels": 7599,
  "cold_ratio_of_saturated": 0.008022542086937794,
  "cold_ratio_pct": 0.802
}
```
Совпадает с заявленными в `scene-artist.md` числами (947206 / 7599 / 0.802%)
до последней цифры. Расхождений нет — метод честный, число подтверждено
независимым запуском того же скрипта на тех же исходных данных.
