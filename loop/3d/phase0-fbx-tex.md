# Phase 0 — потеря второй текстурной карты при экспорте FBX

Задача: найти и починить точку потери tex_1 (второй карты материала) в
конвейере генерация -> Blender -> FBX -> Unity. Гипотеза замера 5-6:
дефект экспорта, не позиционирования и не UV. Роль: mars-asset-smith.
Ограничение: Unity batchmode не запускать (редактор занят URP-переводом
другим агентом). Проверка только чтением файлов / Blender / node-скриптами.

## Шаг 1. Контекст прочитан

- `mars-colony/loop/ours/score-6.md`, раздел «Главная системная причина»:
  FBX-конвертер теряет вторую текстурную карту материала плиты дна карьера
  при конвертации. Живёт 4 замера подряд (3-6), стоит сцене -8 (критерии 3
  и 4 вместе, по -4 каждый).
- Пункт 2 бэклога (там же): «Гипотеза с замера 5 подтверждена этим циклом
  отдельно: FBX-конвертер выгружает только tex_0, вторая карта материала
  плиты (условно tex_1) физически не доезжает до Unity ни при какой
  перезаписи сцены — это не вопрос позиционирования, а вопрос экспорта
  текстур.»
- Роль прочитана: `c:\Ai\Jarvis\.claude\agents\mars-asset-smith.md`. Известный
  факт оттуда: «Текстуры FBX в Unity требуют ExtractTextures + .png + ручной
  досвязки. Дно без текстуры даёт тёмный субмеш.» — это уже намекает, что
  дело может быть и в связке материала в Unity, а не только в самом FBX.
  Проверяю фактом, не домысливаю.
