## Найдено: 2 дефекта

### Дефект 1 — `startConstruction` мутирует чужой снимок состояния (тихая порча)

**Что сломано.** `gameStore.ts::startConstruction` копирует список строек
неглубоко:

```ts
const construction = {
  ...s.construction,
  stock: { ...s.construction.stock },
  builds: s.construction.builds.map((b) => ({ ...b })),
};
const result = startBuild(construction, kind, s.now);
```

`{ ...b }` копирует сам объект `BuildSlot`, но НЕ клонирует его поле
`purchased` — это тот же объект-ссылка, что был у стройки в состоянии ДО
вызова действия. `startBuild` (`domain/construction.ts`) внутри списывает
докупленное по месту:

```ts
if (from_purchase > 0) build.purchased[id] = (build.purchased[id] ?? 0) - from_purchase;
```

Поскольку `build.purchased` — общая ссылка, эта мутация меняет значения и в
объекте, принадлежащем СТАРОМУ (уже показанному, возможно ещё где-то
захваченному) состоянию стора — не только в новом, которое уходит в `set()`.

**Как воспроизвести.** `src/state/__tests__/defects-run5.test.ts`, тест
«старый объект build.purchased, захваченный до старта стройки, не должен
измениться»: докупить 1 модуль (`buyModulesFor`), снять снимок
`build.purchased` ДО вызова `startConstruction`, вызвать `startConstruction`,
проверить, что снимок не изменился. Падает: `{panel: 1}` → `{panel: 0}`.

**Какой инвариант нарушен.** Формально не одна из И-1..И-15, а более базовое
правило проекта — неизменяемость состояния, на которой держится и Zustand
(корректность подписок/ре-рендера), и сейв (детерминированность того, что
уходит в `partialize`). Важно: это ТОЧНО тот риск, который явно осознан и
закрыт в СОСЕДНЕМ действии `buyModulesFor` — его докстринг прямо говорит:
«Копия стройки глубокая по `purchased`... Мутация такого объекта прошла бы
мимо подписчиков — экран не перерисовался бы, а сейв получил бы число,
которого игрок на экране не видел». `startConstruction` эту же мутацию
`purchased` совершает (через `startBuild`), но без глубокой копии — то есть
чинили один из двух путей, второй остался открыт.

**Серьёзность.** Средняя. В одном синхронном потоке выполнения JS эффект не
всегда заметен (старая ссылка просто отбрасывается сборщиком мусора после
`set()`), но при любом коде, держащем ссылку на объект стройки дольше одного
тика — мемоизированный селектор экрана стройки, оверлей подтверждения покупки
с уже отрисованными числами, будущий undo/history-слой — числа под ним
поменяются без единого сигнала об изменении состояния. Класс дефекта — ровно
тот «тихая порча», который явно назван в задании: ничего не падает, тесты
(кроме нового) зелёные, состояние не то, каким его показали игроку. Фикс
дешёвый: `purchased: { ...b.purchased }` при копировании в `startConstruction`,
по образцу `buyModulesFor`.

### Дефект 2 — проверка `SAVE_VERSION` обходится нечисловым/отсутствующим `version`

**Что сломано.** `SAVE_VERSION` документирован как жёсткая граница: «Сейв
прошлой версии выбрасывается целиком... тихо принять состояние неизвестной
формы хуже потери прогресса». В коде за это отвечает `migrate: () => undefined`
— он ВСЕГДА отбрасывает несовпадающую версию, независимо от того, какая она.
Но сама проверка «версия не совпадает» живёт не в нашем коде, а в
`node_modules/zustand/middleware.js`:

```js
if (typeof deserializedStorageValue.version === "number" && deserializedStorageValue.version !== options.version) {
  // ...вызывает migrate, который у нас отбрасывает сейв целиком
} else {
  return [false, deserializedStorageValue.state]; // читает состояние КАК ЕСТЬ
}
```

Если поле `version` в хранимом конверте не число (строка, `null`) или
отсутствует вовсе — ветка «другая версия» не срабатывает, `migrate` не
вызывается, состояние уходит прямо в `merge`. Единственная оставшаяся защита
— `isSave()`, но она сознательно проверяет только ВЕРХНИЙ уровень ключей
(«форма, а не вся модель» — так и задумано, докстринг это подтверждает), а не
вложенные структуры типа `construction.builds[i].purchased` или
`orders[i].positions[i].qty_purchased`. Конверт, у которого верхний уровень
совпадает с текущей формой, но `version` испорчен или отсутствует, проходит
как «свой».

**Как воспроизвести.** `src/state/__tests__/defects-run5.test.ts`, два теста:
конверт с `version: "3"` (строка) и конверт вовсе без поля `version` — оба
принимаются игрой как совместимые (уровень и кредиты из чужого сейва
применяются), хотя ни один из них не является текущей версией 4.

**Что НЕ сломано (проверил отдельно).** Настоящий сейв версии 2 или версии 3
(без полей `drop_floor_guarantee`/`warehouse_avg`, которые появились только в
v4) с корректным ЧИСЛОВЫМ `version: 2` или `version: 3` отбрасывается
правильно — это идёт по нормальному пути `migrate`, и даже если бы он не
сработал, `isSave()` отдельно ловит его по форме (v4 добавила именно новые
ключи верхнего уровня, а не только вложенные поля). Буквальный запрос
«версия 3 и версия 2 выбрасываются, не читаются частично» для НОРМАЛЬНОГО
случая подтверждён — не дефект.

**Какой инвариант нарушен.** Не игровой И-1..И-15, а прямое обещание раздела
«Сохранение прогресса» в `gameStore.ts` («сейв другой версии... выбрасывается
целиком») и общее правило проекта «тихая порча хуже явной ошибки». Обходится
конкретно версионирование — механизм, специально введённый ПОСЛЕ того, как
похожие тихие порчи (Д-1, Д-18, Д-28) уже один раз стоили вместимости склада
навсегда.

**Серьёзность.** Низкая-средняя. Требует, чтобы поле `version` конкретно
исказилось или пропало (ручная правка localStorage, порча стороннего
расширения браузера, баг сериализации в другой версии zustand) — это не
дефект, который срабатывает сам в обычной игре. Но защита от него
декларирована («тихо принять состояние неизвестной формы хуже потери
прогресса») и полагается на реализацию, которая не покрывает этот конкретный
случай, а существующий набор тестов на «битое и чужое хранилище» специально
перебирает варианты порчи ключа и этот вариант пропустил.

## Проверено и не сломалось (кроме отмеченного выше)

- Докупка модулей (`buyModules`/`missingFor`/`modulePurchasePrice`): нельзя
  купить дважды за одну и ту же цену (после покупки `missingFor` для этого
  модуля обнуляется), нельзя получить отрицательное количество, докупленное
  не обходит лимит склада модулей задним ходом (это сознательное решение
  дизайна — `purchased` физически не на складе, докстринг явно это объясняет).
- `startBuild`: списание сначала из `purchased`, потом из `stock` — арифметика
  не даёт отрицательных остатков ни при каком порядке докупки/пополнения
  склада, проверено вручную и первичным исследовательским тестом.
- Три инварианта дроп-роллера: скользящее среднее корректно ведёт себя при
  скачке часов назад (no-op) и вперёд/долгом оффлайне (alpha=1, среднее =
  текущий остаток — задокументированное поведение); двухэтапный выбор
  тир/предмет действительно держит заявленные веса тиров независимо от
  pity/анти-стокпайла (уже покрыто существующим property-тестом); floor
  guarantee не срабатывает дважды за одно прибытие (`break` после первого
  совпадения) и не оставляет вторую стройку голодать навсегда (счётчики
  независимы, расходятся за 1-2 прибытия).
- Смешанная позиция заказа дрона (часть со склада, часть докупкой): отправка,
  выброс и подсчёт последствий выброса (`discardImpact`) везде считают через
  `stockedIn`/`purchasedIn` (по количеству), а не через `filled_by` (по
  последнему взносу) — класс Д-1/Д-18, который ловили у шаттла, у дрона не
  воспроизводится.
- Стык докупки (И-12) и гарантии (И-7/И-11): И-11 корректно вычитает
  `purchased` при расчёте покрытия стройки; И-7 (pity/анти-стокпайл) читает
  валовую потребность без вычета `purchased` — это ЗАРЕГИСТРИРОВАННОЕ решение
  ([[spec-prototype-build]], реестр, пункт 19, ждёт подтверждения владельца),
  а не скрытый баг. Эффект расхождения — тот же, что описан в реестре
  (щедрость к игроку, экономически безопасно: лишний модуль уходит в общий
  склад для других строек). Дополнительного вреда сверх задокументированного
  не нашёл — не завожу как отдельную находку, это несогласие с уже принятым
  решением дизайна, а не необнаруженный баг.
- Гейт: `npm run test:gate` — 581/581 зелёных после добавления файла находок,
  `tsc -b` чист, новый файл не участвует в гейте (паттерн исключения
  `**/*defects-*.test.ts`).
