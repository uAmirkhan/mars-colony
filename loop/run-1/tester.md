## Находки (шкала C)

**C-1. Докупка поверх частичной погрузки запирает товар на складе навсегда.**
Класс: тихая порча данных + нарушен инвариант.
`src/domain/shuttle.ts:307` — `buyoutSlot` ставит `slot.filled_by = 'purchase'`,
перетирая `'self'`. `src/domain/shuttle.ts:226` — `depart` пропускает такой отсек
целиком (`continue`), не вызывая `shipReserved`. Отсек просит 5, на складе 3:
игрок грузит 3 (резерв, `filled_by='self'`), докупает остаток (`filled_by='purchase'`),
и три единицы остаются с `qty=3, reserved=3` навсегда. `availableOf` = 0, вернуть
нечем (отмены у шаттла нет по И-12), емкость склада потеряна. Повторяется каждый рейс.
Нарушена семантика `deliver` (`warehouse.ts:12`).
Доказано: 3 красных теста, один — свойство на `fast-check`. Контрпример, сокращенный
самим свойством: `[{slot:1,buy:false},{slot:2,buy:false},{slot:2,buy:true},{slot:0,buy:false}]`.
Существующий тест «после отправки резерв не висит» (`shuttle.test.ts:229`) проверяет
только путь без докупки.

**C-2. Первый рейс на бедном складе вырождается, на пустом — софтлок насмерть.**
Класс: тихая порча данных; для шкалы G — цикл непроходим.
`src/domain/shuttle.ts:144-151`, ветка `if (ctx.is_first_trip)`: товар, которого нет
на складе, выбрасывается (`i -= 1; continue`), пул уже уменьшен `splice`, замена не
берется. ТЗ шаттла 2.1 требует ровно 3 отсека.
Склад с одним товаром → рейс из 1 отсека вместо 3. Склад пуст → рейс из **0 отсеков**:
`allSlotsLoaded([])` всегда false, `gameStore.tick` (`gameStore.ts:302-307`) выдает
новый рейс только из `COOLDOWN`, выхода нет. Шаттл — единственный источник
строй-модулей (И-1), значит мертвы стройка, апгрейд склада и вся прогрессия.
Состояние достижимо штатно: продать все на рынке до ур.5.
Доказано: 2 красных в домене + 2 красных в сторе.
Почему 430 зеленых это пропустили: все тесты генератора кормят его набитым складом
(`stockedWarehouse(POOL, 30/40)`), включая тест «FTUE: ровно три отсека»
(`shuttle.test.ts:81`).

**C-3. Pity растет по модулям, которые никому не нужны.**
Класс: нарушен инвариант И-7 + тихая порча.
`src/domain/droproller.ts:194`: `next_pity[id] = dropped.has(id) ? 0 : (ctx.pity[id] ?? 0) + 1`
— инкремент безусловный. Канон `tz-common-systems-mars.md:400-404` требует
`elif isNeededForActiveContext(item, ...)`. ТЗ шаттла 8.1 повторяет словами.
Следствие: модуль, не нужный двадцать прибытий, в момент старта стройки приходит
с уже взведенным pity и сразу получает `PITY_MULTIPLIER=2`, отбирая вес у того,
чего игрок ждет. И-7 работает наизнанку.
Доказано: красный тест, фактическое `next_pity` = 1 при `need = {}`.

**C-4. Роллер возвращает индекс отсека, которого нет.**
Класс: тихая порча данных (низкая серьезность — через интерфейс сейчас недостижимо).
`src/domain/droproller.ts:186-187`: при `slot_count = 0` наружу уезжает
`floor_forced_slot = -1` вместо `null` (по контракту это значит «гарантия сработала»),
на массив `modules` вешается свойство `"-1"`. Потребитель, читающий
`slots[roll.floor_forced_slot]`, получит `undefined`; `shuttle.ts:233` промолчит.
Доказано: красный тест, фактическое `-1` вместо `null`.

**C-5. Порог И-8 «производимо за 30 минут» считается без цепочки рецепта.**
Класс: нарушен инвариант И-8. Серьезность средняя, достижимо с ур.11.
`src/domain/shuttle.ts:95-98`: `isEasy` принимает `qty` и не использует его во второй
ветке, читая только `GOODS[good_id].prod_time_sec`. Комбинезон формально проходит
порог (1800 сек = ровно 30 мин), фактически требует 2 ткани и 4 хлопка, суммарно
7200 сек. Генератор считает такой рейс полностью легким, пересборка состава не
срабатывает ни разу за 40 попыток.
Обход цепочки в проекте уже написан: `expandProductionChain`, `src/domain/rushcost.ts:54`.
Инструмент есть, здесь не позван.
Доказано: красный тест, фактическая доля легких позиций 0 при требуемых 0.6.

**C-6. Лимит склада строй-модулей не апгрейдится ничем.**
Класс: механика из спеки без единого теста.
Каркас раздел 6 (`mars-colony-frame.md:181`): «Строй-модули хранятся отдельным
лимитом 100 и апгрейдятся тем же зданием». `src/domain/construction.ts:129-131` —
`applyBuildEffect` поднимает только товарную емкость; `:56-58` — `moduleSpaceLeft`
читает константу `MODULE_STOCK_CAP` напрямую. Механики нет вовсе.
Цена не косметическая: при забитом складе модулей `collectContainerAt`
(`gameStore.ts:389`) отказывает, контейнеры остаются несобранными, `startCooldown`
не вызывается, новый заказ не выдается — шаттл встает целиком, как в C-2.
Доказано: красный тест.

## Находки без падающего теста (доказательство — grep)

**C-7. И-10 не реализована ни для одной механики.**
`ORDER_FEASIBILITY_DEADLINE_SHARE = 0.6` объявлена в `src/domain/config/economy.ts:238`
и не упоминается больше нигде: `rg -n "ORDER_FEASIBILITY" src/` дает одну строку —
саму декларацию. Каркас 3.1 и ТЗ шаттла 3 объявляют И-10 действующей.
Красный тест не написан сознательно: у шаттла нет дедлайна вообще, поэтому
знаменатель формулы не определен. Это вопрос к спеке, отдан ревьюеру.
Класс: механика из спеки без единого теста.

**C-8. Тестов-свойств в проекте не было ни одного.** `fast-check` стоит в
devDependencies с 4.9.0, `rg "fast-check|fc\." src/` до правок не находил ничего.
Все 430 зеленых — примеры. C-1 нашелся именно свойством: три существующих примера
покрывали докупку в пустой и в закрытый отсек, но не комбинацию.

**Замечание к дизайну, не дефект.** `generateTrip` называет переменную `best`, но
присваивает ее на каждой итерации (`shuttle.ts:181`), поэтому возвращается не лучший
состав из сорока, а последний. Спека выбора лучшего не обещает.

## Шкала G — факты, без оценок

**Обработчиков ввода в Unity-сборке нет ни одного. Компонентов, реагирующих на клик,
нет ни одного. Игровой логики на C# нет ни строки.**

1. Файлов `.cs` во всем `Assets` — **два**, оба в `Assets/Editor/`: `BuildScript.cs`
   (headless-сборка) и `SceneBuilder.cs` (раскладка спрайтов). Оба используют
   `using UnityEditor` и лежат в папке `Editor`, то есть в плеер не компилируются
   вообще. Ни одного `MonoBehaviour` в проекте нет.
2. Состав сцены `Assets/Scenes/Main.unity` целиком: 38 GameObject, 38 Transform,
   37 SpriteRenderer, 1 ортографическая камера, плюс настройки. Ни одной ссылки
   `m_Script`. Ноль `Canvas`, ноль `EventSystem`, ноль `GraphicRaycaster`, ноль
   `Button`, ноль `Collider`, ноль `Rigidbody`.
3. `Packages/manifest.json` подключает `com.unity.ugui` и `com.unity.modules.ui`,
   но в сцене этих компонентов нет: пакеты подключены, интерфейс не собран.

**Основной цикл кликами не проходится ни на одном шаге.** Заказать производство
нельзя — нет ни кнопки, ни коллайдера, ни скрипта, принимающего нажатие. То же для
«забрать на склад», «загрузить шаттл», «отправить», «получить модули», «начать
стройку». В плеере нет ни одного объекта, состояние которого может измениться
после запуска.

**HUD отсутствует.** Ни счетчиков валют, ни ленты отсеков, ни единого элемента
интерфейса на кадре.

Вся игровая логика прототипа живет в TypeScript (`mars-colony/src/domain/`) и в
Unity-трек не перенесена никак: ни портированного домена, ни моста, ни заглушки
состояния.
