## 1. Шаттл = поезд Township, не заказы

«Шаттл — это аналог поезда. Поезд приходит с определёнными требованиями, ему нужен тот или иной ресурс разных видов.
Заказы были у вертолёта — у нас эту функцию выполняют дроны. У шаттла механика: увёз материал, пропал на время,
пришёл с материалом для прокачки базы. Такой ресурс нигде нельзя получить, кроме как от него».

### 1.1 Что уже совпадает с ТЗ и остаётся
- Отсеки 3–5 с требованием «товар × N», загрузка со склада по тапу, рейс по таймеру, награда — строй-модули и XP (`tz-shuttle` п.2). Домен `Shuttle.cs` это делает.
- Строй-модули приходят **только** с шаттлом (единственный источник), копятся на складе во вкладке «Модули», тратятся на расширение склада и будущую стройку.

### 1.2 Что неверно сейчас и меняется
| Было | Должно быть |
|---|---|
| Заголовок «Шаттл · заказ №N», строки-список «товар 3/5 … ЗАГРУЗИТЬ» | Слово «заказ» у шаттла запрещено — оно только у дронов. Заголовок «Грузовой шаттл», под лентой — **сцена как у Ж/д станции**: силуэт шаттла и ряд из 3–5 **контейнеров** (референс — вагоны photo_15): в каждом иконка товара и «×N», загруженный контейнер закрывается зелёной галочкой. |
| Действие в строке | Тап по контейнеру → карточка (как photo_15): «Награда: [иконка модуля] + [звезда] XP», строка «есть/нужно» с иконкой товара, кнопка **ЗАГРУЗИТЬ** (кнопка «Запрос» союзнику — вне скоупа, не рисуем). |
| Отправка | Как в ТЗ п.2.3: загружен последний контейнер → люки закрываются, огонь, взлёт. Кнопки «Отправить» нет. |
| В рейсе | Панель показывает табло с пунктом назначения («ОРБИТАЛЬНАЯ СТАНЦИЯ», референс photo_11: перекидное табло) и таймер «Прибытие через ч:мм», кнопка «Ускорить» за изотопы по И-6. |
| Прибытие | Шаттл садится с **контейнерами наград** на площадке: 1 отсек = 1 контейнер модулей, тап — зачисление с всплеском «+модуль»; после сбора всех — открываются люки нового рейса (кулдаун по ТЗ). |
| Пузырь на карте | Простаивает с открытыми люками и на складе есть хоть что-то для загрузки → пузырь с иконкой шаттла; в рейсе → ничего (таймер только в панели); прилетел с наградой → пузырь-галочка. |

### 1.3 Требование «минимум три ресурса разных видов»
«У нас три разных модуля, чтобы он мог запрашивать минимум три ресурса».
Толкование (подтвердить): генератор рейса берёт отсеки из **не менее трёх разных производственных цепочек** базы
(теплицы / пищевой / водная / атмосферный / добыча), не три отсека одного товара. В домене: `generateTrip` получает
`available_goods`, сгруппированные по `required_building`, и обязан задействовать ≥3 групп, если они есть.
Подтверждено заказчиком 06.09: отсеки рейса — из не менее трёх разных цепочек производства.

## 2. Теплица = грядки, не фабрика

«Посадить растение в теплицу выглядит, как будто что-то создать в пищевом заводе, но это не так. Должны быть грядки
либо горшки: при открытии теплицы открывается интерфейс на полэкрана с горшками, изолированными грядками, длинными
горшками. Как в Township: оп — выбрал ресурс, оп — посадил».

### 2.1 Как в Township (референс photo_37, photo_51)
Поле — это клетки на карте без панели. Тап по пустой клетке → веер культур рядом с клеткой; ведёшь культуру по клеткам —
сеешь. Растущая клетка по тапу показывает пузырь «Хлопок · 13м 02с · [ускорить 65]». Созревшая — тап/протяжка серпом собирает.
У нас теплица — купол, внутрь камера не смотрит, поэтому «клетки» переносятся в интерфейс.

### 2.2 Экран теплицы (на полэкрана, снизу)
- Лента-заголовок «Теплица N», крест. Тело — **вид грядок сверху**: сетка длинных горшков (поддонов), по умолчанию **6 горшков
  в 2 ряда по 3** (число — параметр ступени базы, см. концепцию уровней в `SPEC-NOCH-3-igra.md`).
- Горшок — отдельный слот домена (`FieldSlot`): пусто / растёт (иконка ростка на стадии + маленькая полоса) / готово (спелый предмет, подпрыгивает).
- **Посев:** тап по пустому горшку → над горшком веер культур (иконки с ценой посева, как веер Township); тап по культуре — посеяно в этот горшок,
  веер остаётся открытым, и следующие тапы по пустым горшкам сеют ту же культуру (режим «кисть»), пока не тапнуть в пустоту или крест.
  Дополнительно: протяжка пальцем от горшка к горшку сеет по пути (как в Township); для мыши — то же протяжкой с зажатой кнопкой.
- **Сбор:** тап по спелому горшку — урожай улетает в счётчик склада (+XP всплеском); протяжка по нескольким спелым — собирает все.
  Если склад полон — горшок трясётся, всплывашка «Склад полон».
- **Растущий горшок** по тапу показывает пузырь «Соя · 0:45 · ⚡ ускорить N» (карточка-подсказка заказчика).
- Лоток рецептов и коробки-конвейер в теплице **не используются** — это язык фабрик.
- Пузырь над куполом на карте: есть спелые горшки → галочка; все пусто и это текущая цель → пузырь с иконкой культуры; растёт → ничего.

### 2.3 Домен
- `ColonyState.fields`: по одному `FieldSlot` на горшок: `3 теплицы × 6 = 18` слотов, индекс горшка = `teplitsa*6 + gorshok`.
  Урожай с горшка — `HarvestQty(good)` как сейчас с грядки (то есть теплица даёт до 6 урожаев за цикл — это меняет экономику,
  см. решение ниже). Сохранение — тот же плоский снимок, старые сохранения с 4 грядками мигрируются в первые 4 горшка.
Решение заказчика 06.09: урожай с поддона = `ceil(HarvestQty / 6)`, производительность теплицы прежняя, просто разбита на поддоны.
Число поддонов в теплице — параметр ступени (`PODDONOV_V_TEPLITSE`, сейчас 6); прокачка теплицы добавляет поддоны — в планах,
в реализации пока константа. Открывается один купол = одна теплица с её поддонами.

## 3. Маркеры на карте — правила геймдизайнера («на сцене хаос с иконками»)

Диагноз по кадру 140: четыре языка маркеров одного силуэта (пузырь-иконка, пузырь-таймер, галочка, пин цели), 7 маркеров
плюс HUD одновременно, пустые пузыри без иконки, пин цели перекрывает галочку над тем же куполом, размер маркера не зависит
от размера здания, верхние пузыри сливаются с рядом иконок HUD.

Правила (реализуемые кодом):
1. **Всегда виден только «готово»** (зелёный пузырь с галочкой) — единственный маркер, обязанный читаться с любой точки карты.
2. **«Можно начать» показывается только над зданием текущей цели** (карточка ЦЕЛЬ). Остальные простаивающие — без маркера.
   Число кремовых пузырей = число активных целей (обычно 1).
3. **Таймеров над зданиями на карте нет.** Остаток времени — только в панели здания и по тапу. Работа видна анимацией самого объекта
   (машины едут, шнек крутится, дым/шестерёнка у фабрики — по возможности).
4. **Не больше трёх маркеров состояния в кадре.** Сверх — приоритет ближайшему к центру экрана, остальные скрыть.
5. **Размер пузыря — доля высоты здания на экране**: 18–22 %, но не меньше 40 px и не больше 70 px.
6. **«Можно начать» и «готово» различаются оболочкой**, не только пиктограммой: кремовый пузырь против зелёного (галочка с зелёной заливкой всего пузыря — заказать элемент).
7. **Пустой пузырь запрещён**: нет иконки для состояния — маркер не рисуется.
8. **Пин цели убрать**: карточка ЦЕЛЬ уже называет объект и ведёт к нему кнопкой; вместо пина — пульсирующий контур здания цели (тот же outline, что у выделения).
9. **При открытой панели здания**: карточка ЦЕЛЬ, маркеры и подпись-табличка над зданием скрываются, фон приглушается одним слоем.
